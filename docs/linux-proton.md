# Linux Proton fast path

The measured fast path requires the paired Proton build referenced by the `proton-ge` submodule. Its Wine imports section memory as dma-bufs through `/dev/udmabuf`, and its vkd3d-proton supports a configurable view-heap size. A compatible device, permissions, and an installed build are required; a submodule checkout alone is not an installation.

The launcher selects the custom path by checking its `d3d12core.dll` for `VKD3D_VIEW_HEAP_DESCRIPTORS`. The Steam wrapper uses the same capability check and stages the selected Proton's vkd3d DLLs. With that capability it sets `VICTORY_PORT_CONSTANTS=1`, `WINE_VICTORY_LOCAL_VIEWS=1`, `VKD3D_DISABLE_EXTENSIONS=VK_EXT_descriptor_heap`, and `VKD3D_VIEW_HEAP_DESCRIPTORS=4194304`. Without it, constant porting is disabled: enabling it on another Proton can produce a black picture.

Both launcher paths set `VICTORY_NO_WATCHDOG=1`, `VICTORY_RT_FALLBACK_NO_BVH=1`, `VICTORY_AMBIENT=0.35`, and `VICTORY_AMBIENT_SHADE=0`. The normal profile also sets `VICTORY_TEXTURE_NO_WAIT=1`, `VICTORY_RELAY=2`, `VICTORY_WIDE_BACK=1`, `VICTORY_CARD_REHASH_RUNS=1`, `VICTORY_JOIN_COPIES=1`, `VICTORY_INDIRECT_WINDOW=1`, `VICTORY_RELAY_COPY=1`, `VICTORY_CARD_STEPS=2`, `VICTORY_INDIRECT_BATCH=2`, `VICTORY_MAP_THREADS=1`, `VICTORY_CARD_AWAKE=1`, `VICTORY_SHOW_AFTER=1`, `VICTORY_THIN=1`, `VICTORY_JOIN_PARTS=8`, `VICTORY_UPLOAD_AHEAD=1`, `VICTORY_PORT_DESCRIPTORS=1`, `VICTORY_PORT_CBV=1`, `VICTORY_PORT_GUARD=1`, `VICTORY_PORT_JOURNAL=1`, `VICTORY_WC_NO_BACK=1`, and `VICTORY_CARD_BUFFERS_MIN_MB=1`. The standalone launcher also has a `--safe` option. The Steam wrapper's profile has not yet been tested in a game run.

The paired Proton revision adds synchronous guard handling when supported by Wine; `VICTORY_SYNC_GUARDS=0` disables it. Unsupported Wine versions retain the existing behavior. The standalone launcher defaults to the paired build.

BCPack decoding selects AVX2 on supported CPUs and otherwise uses scalar lanes. In diagnostics builds, `VICTORY_BCPACK_DUMP` selects a folder for captured compressed streams; it is unset by default. The fork reported 58.3 to 115 MB/s over 400 streams on one native thread; these results have not been independently reproduced.
